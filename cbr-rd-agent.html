CBR-augmented R&D-Agent

An autonomous data science agent that keeps a memory of past experiments and reuses what worked.

View on GitHub ↗ Preprint on arXiv ↗
Current status

A first research approach, still far from practical use. It was built to complete a project assignment, including a preprint, and has only been tested on two Kaggle competitions. This page describes what exists today and where its limits are.

Where the idea came from

The idea goes back to discussions at IDIADA when agent systems were first appearing in industry. For a small team, as in many small and medium-sized companies, the open question was whether such agents are usable at all and what it would take.

Two things got the project started. A further-education certificate in applied AI at Technische Hochschule Ingolstadt required a project with a publishable paper, and I chose this topic. At the same time, I see it as a long-term development project that this assignment kicked off.

The long-term goal

An autonomous data science agent that draws on the experience and past projects of a company team. It would solve new data science tasks on its own and store new solutions back into a shared database. Over time it would build up a set of solutions that fit the team's own work and can be reused.

What exists today

The project extends Microsoft's open-source R&D-Agent, which uses a language model to propose, implement and evaluate data science experiments.

  • Experiment memory. Successful experiments are stored as cases and retrieved when a similar task comes up. Failed attempts are remembered too, so they are not repeated.
  • Quality check before storing. Only results that run cleanly, improve on the starting point and add something new are kept.
  • Small, locally deployable model. The agent runs on Gemma 4, an open model that can run on a company's own hardware.
  • Comparison with and without memory on two Kaggle competitions, with statistical tests.

First results and limits

The first experiments point in a direction, but with only a few runs per setup they are not yet statistically robust. Setup, figures and a detailed discussion are in the preprint.

  • Tested on two Kaggle competitions only. The method has not been generalized to other tasks.
  • Few runs per setup, so all effects are preliminary.
  • The memory has only been used within one task so far. Reuse across tasks, the actual long-term goal, is not tested yet.

Next steps

I plan to continue the project in further certificate courses: improve the method and the preprint, then use improved versions to produce results that hold up at scientific conferences, which I want to publish as an independent researcher.
